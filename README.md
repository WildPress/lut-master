# LUT Master

Android app that applies camera-log and film-style LUTs to video, with a live preview and export. Prototype, not yet device-tested beyond one Samsung Galaxy S26.

## Workflow

Two stages, with Rec.709 as the common intermediate:

1. **Input transform** converts your camera's log footage (curve and gamut) to Rec.709. You pick the profile yourself, since log files rarely say what they are.
2. **Look** is a creative LUT that takes Rec.709 in and gives Rec.709 out, so any look works with any camera.

The pair is composed into one 33-point LUT for both preview and export. "Load .cube..." adds your own look (tick "Full LUT" to skip the input transform); "Load input .cube..." adds your own input transform, saved on the device.

## Bundled LUTs

Generated by `lut-gen/generate.py` (33-point .cube, red fastest).

- **Input transforms:** Sony S-Log3 / S-Gamut3.Cine, Panasonic V-Log, Fujifilm F-Log and F-Log2, Nikon N-Log, DJI D-Log (Zenmuse spec, consumer D-Log M may differ), Rec.709 passthrough. All except S-Log3 were checked against the manufacturers' published data sheets; the S-Log3 constants and gamut matrix have not been re-checked against Sony's own document.
- **Not included:** Canon C-Log2/3, Apple Log, Blackmagic Film Gen5, S-Gamut3 (no verified primary source yet).
- **Looks:** film-style looks, tinted-black looks and foggy-forest looks. Names such as "Kodak Portra 400 style" are rough approximations made for this project. They are not measured profiles, not official, and not endorsed by any film maker.
- **Samsung Log:** Samsung's official "Log to Rec709" LUT needs a Samsung sign-in to download and is not redistributed here. Download it from Samsung's developer site and either load it in the app with "Load input .cube..." or drop it in `app/src/main/assets/luts/input/` before building.

## Build

Docker only, no host Java or Android SDK needed:

```sh
./build.sh   # runs unit tests and assembleDebug, writes ./app-debug.apk
```

Debug signing keys are kept stable between builds so new APKs install over old ones: put a keystore at `.signing/debug.keystore` (git-ignored) to use your own, otherwise a Docker volume holds one.

`test-assets/test-clip.mp4` is git-ignored; make one with `docker build -t lut-master-ffmpeg -f Dockerfile.ffmpeg .` then
`docker run --rm -v "$PWD/test-assets":/out lut-master-ffmpeg -f lavfi -i testsrc2=size=1280x720:rate=30 -f lavfi -i sine=frequency=440 -t 5 -c:v libx264 -pix_fmt yuv420p -c:a aac -shortest /out/test-clip.mp4`.

## Known caveats

- Live preview uses a `TextureView` surface. With the default `SurfaceView`, Media3 applied no effect on the test phone.
- Export uses Media3 Transformer. After export the app compares a frame to the source and reports whether the LUT was applied.
- Tested on one Galaxy S26 only. 10-bit and flagged-HDR clips may export differently from the preview.
